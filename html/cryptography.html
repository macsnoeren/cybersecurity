CryptographyCryptografie

Cryptography secures information and communication. It enables confidentiality (encryption), integrity (hashing), authenticity (signatures), non-repudiation, and authentication & authorisation. Real implementations combine multiple primitives — no single algorithm does everything.

01 · Hashing

Secure HashingVeilig Hashen

A cryptographic hash function maps data of any size to a fixed-size digest in a one-way, deterministic fashion. The same input always produces the same output, but it must be computationally infeasible to reverse the hash or find two inputs that produce the same hash (collision resistance). Hashing is the foundation of integrity, password storage, digital signatures, and MACs.

Een cryptografische hashfunctie brengt data van elke grootte naar een digest van vaste grootte op een eenrichtings, deterministische manier. Dezelfde invoer produceert altijd dezelfde uitvoer, maar het moet computationeel onhaalbaar zijn om de hash om te keren of twee invoeren te vinden die dezelfde hash produceren (botsingsbestendigheid). Hashing is de basis van integriteit, wachtwoordopslag, digitale handtekeningen en MAC's.

02 · Symmetric02 · Symmetrisch

Symmetric CryptographySymmetrische Cryptografie

The same secret key is used for both encryption and decryption. Extremely fast — orders of magnitude faster than asymmetric crypto. Used for bulk data encryption (files, TLS record layer, disk encryption). The core challenge: how do two parties securely agree on the shared key? That's solved by key exchange (asymmetric crypto).

Dezelfde geheime sleutel wordt gebruikt voor zowel encryptie als decryptie. Extreem snel — ordes van grootte sneller dan asymmetrische crypto. Gebruikt voor bulk data-encryptie (bestanden, TLS record layer, schijfencryptie). De kernuitdaging: hoe komen twee partijen veilig een gedeelde sleutel overeen? Dat wordt opgelost door sleuteluitwisseling (asymmetrische crypto).

AES — Advanced Encryption Standard
FIPS 197 · NIST 2001

The world's most widely deployed symmetric cipher. AES operates on 128-bit blocks using 128, 192, or 256-bit keys. It is a substitution-permutation network with 10–14 rounds depending on key size. Hardware acceleration (AES-NI) makes it extremely fast.

Wereldwijd het meest gebruikte symmetrische cijfer. AES werkt op 128-bit blokken met sleutels van 128, 192 of 256 bits. Het is een substitutie-permutatie netwerk met 10–14 rondes afhankelijk van de sleutelgrootte. Hardwareversnelling (AES-NI) maakt het extreem snel.

03 · Asymmetric03 · Asymmetrisch

Asymmetric (Public-Key) CryptographyAsymmetrische (Publieke Sleutel) Cryptografie

Uses a mathematically linked key pair: a public key (share freely) and a private key (keep secret). Anything encrypted with the public key can only be decrypted with the private key, and vice versa. Solves the key distribution problem — but is 1000–10,000× slower than symmetric crypto. In practice it is used for key exchange and digital signatures, not bulk encryption.

Gebruikt een wiskundig gekoppeld sleutelpaar: een publieke sleutel (vrij delen) en een privésleutel (geheim houden). Alles wat versleuteld is met de publieke sleutel kan alleen ontsleuteld worden met de privésleutel, en vice versa. Lost het sleuteldistributieprobleem op — maar is 1000–10.000× langzamer dan symmetrische crypto. In de praktijk gebruikt voor sleuteluitwisseling en digitale handtekeningen, niet voor bulkencryptie.

RSA
RFC 8017 (PKCS#1)

Based on the hardness of factoring large integers. Still widely used for TLS certificates, JWT (RS256), and legacy systems. Requires large key sizes for security.

Elliptic Curve Cryptography (ECC)
NIST SP 800-186

Based on the algebraic structure of elliptic curves over finite fields. Provides equivalent security to RSA with much smaller key sizes — a 256-bit ECC key is as strong as a 3072-bit RSA key. Preferred for modern systems.

Gebaseerd op de algebraïsche structuur van elliptische krommen over eindige lichamen. Biedt gelijkwaardige veiligheid aan RSA met veel kleinere sleutelgroottes — een 256-bit ECC-sleutel is even sterk als een 3072-bit RSA-sleutel. Voorkeur voor moderne systemen.

Key Derivation from Passwords (KDF)
PBKDF2 · bcrypt · Argon2id · scrypt

Passwords have low entropy and cannot be used directly as cryptographic keys. A Key Derivation Function (KDF) is deliberately slow and memory-intensive to thwart brute-force and GPU attacks. Always use a unique per-user salt.

Wachtwoorden hebben lage entropie en kunnen niet direct als cryptografische sleutels worden gebruikt. Een Key Derivation Function (KDF) is opzettelijk traag en geheugenintensief om brute-force en GPU-aanvallen tegen te gaan. Gebruik altijd een unieke salt per gebruiker.

Secret Sharing (Shamir's Secret Sharing)Geheim Delen (Shamir's Secret Sharing)
Shamir 1979

A secret can be split into n shares such that any k of n shares can reconstruct it, but k−1 shares reveal nothing. Used in distributed key management, cryptocurrency wallets, and cryptographic ceremonies.

How TLS 1.3 WorksHoe TLS 1.3 Werkt

🔒 TLS 1.3 Handshake Flow🔒 TLS 1.3 Handshake Flow

1

ClientHello

Client sends: supported cipher suites, TLS version, key_share (ephemeral X25519/P-256 public key), random nonce. No round-trip needed — client speculatively includes key share.

Client stuurt: ondersteunde cipher suites, TLS-versie, key_share (tijdelijke X25519/P-256 publieke sleutel), willekeurige nonce. Geen round-trip nodig — client voegt speculatief key share toe.

2

ServerHello + Key DerivationServerHello + Sleutelafleiding

Server responds with its own key_share, selected cipher suite. Both sides now compute the shared secret via ECDHE and derive the handshake traffic keys using HKDF.

Server antwoordt met eigen key_share, geselecteerde cipher suite. Beide kanten berekenen nu het gedeelde geheim via ECDHE en leiden de handshake-verkeerssleutels af met HKDF.

3

Server Certificate + SignatureServercertificaat + Handtekening

Server sends its X.509 certificate (public key + identity) and a signature over the handshake transcript. Client verifies certificate chain up to a trusted root CA (PKI).

Server stuurt zijn X.509-certificaat (publieke sleutel + identiteit) en een handtekening over het handshake-transcript. Client verifieert certificaatketen tot aan een vertrouwde root CA (PKI).

4

Finished Messages (Authenticated)Finished Berichten (Geauthenticeerd)

Both sides exchange Finished messages — an HMAC over the full handshake. This confirms both parties derived the same keys and detects any tampering.

Beide kanten wisselen Finished berichten uit — een HMAC over de volledige handshake. Dit bevestigt dat beide partijen dezelfde sleutels hebben afgeleid en detecteert manipulatie.

5

Application Data (AES-256-GCM or ChaCha20-Poly1305)Applicatiedata (AES-256-GCM of ChaCha20-Poly1305)

All further data is encrypted with AEAD ciphers using the derived session keys. TLS 1.3 has perfect forward secrecy — past sessions remain safe even if the server's private key is later compromised.

Alle verdere data wordt versleuteld met AEAD-cijfers met behulp van de afgeleide sessiesleutels. TLS 1.3 heeft perfect forward secrecy — eerdere sessies blijven veilig, zelfs als de privésleutel van de server later lekt.

ℹ️
TLS 1.3 improvements over TLS 1.2: Removed RSA key exchange (no forward secrecy), removed weak ciphers (RC4, 3DES, MD5/SHA-1), reduced handshake from 2 round-trips to 1, added 0-RTT resumption. Always disable TLS 1.0 and 1.1.
TLS 1.3 verbeteringen t.o.v. TLS 1.2: RSA-sleuteluitwisseling verwijderd (geen forward secrecy), zwakke cijfers verwijderd (RC4, 3DES, MD5/SHA-1), handshake verminderd van 2 round-trips naar 1, 0-RTT hervatting toegevoegd. Schakel TLS 1.0 en 1.1 altijd uit.
How PKI WorksHoe PKI Werkt

🏛️ Public Key Infrastructure (PKI)🏛️ Public Key Infrastructure (PKI)

1

Certificate Authorities (CAs)

A CA is a trusted third party that signs X.509 certificates. Root CAs are self-signed and their public keys are pre-installed in browsers/OS. Intermediate CAs are signed by roots to limit blast radius of compromise.

Een CA is een vertrouwde derde partij die X.509-certificaten ondertekent. Root CA's zijn self-signed en hun publieke sleutels zijn vooraf geïnstalleerd in browsers/OS. Intermediate CA's worden ondertekend door roots om de impact van een compromis te beperken.

2

Certificate Issuance (CSR)Certificaatuitgifte (CSR)

An entity generates a key pair, creates a Certificate Signing Request (CSR) containing their public key and identity (domain name, org). The CA verifies identity (DV/OV/EV) and signs the certificate with its private key.

Een entiteit genereert een sleutelpaar, maakt een Certificate Signing Request (CSR) met hun publieke sleutel en identiteit (domeinnaam, org). De CA verifieert de identiteit (DV/OV/EV) en ondertekent het certificaat met zijn privésleutel.

3

Certificate ValidationCertificaatvalidatie

Client receives server cert → builds chain to trusted root → verifies each signature → checks validity dates → checks OCSP/CRL for revocation. All checks must pass.

Client ontvangt servercertificaat → bouwt keten naar vertrouwde root → verifieert elke handtekening → controleert geldigheidsdata → controleert OCSP/CRL op intrekking. Alle controles moeten slagen.

4

Certificate Transparency (CT)

All publicly trusted certificates must be logged to public CT logs (RFC 6962). Allows domain owners to detect mis-issued certificates. Browsers reject certs not in CT logs.

Alle publiek vertrouwde certificaten moeten worden gelogd in openbare CT-logs (RFC 6962). Stelt domeineigenaren in staat om verkeerd uitgegeven certificaten te detecteren. Browsers weigeren certificaten die niet in CT-logs staan.

5

Let's Encrypt & ACME

Free, automated certificate issuance via the ACME protocol (RFC 8555). Proves domain control by serving a challenge token. Used by millions of websites — eliminated the cost barrier to HTTPS.

Gratis, geautomatiseerde certificaatuitgifte via het ACME-protocol (RFC 8555). Bewijst domeincontrole door een challenge token te serveren. Gebruikt door miljoenen websites — heeft de kostenbarrière voor HTTPS weggenomen.

How Blockchain Uses CryptographyHoe Blockchain Cryptografie Gebruikt

⛓️ Blockchain Cryptographic Primitives⛓️ Blockchain Cryptografische Primitieven

1

Merkle Trees (SHA-256)

All transactions in a block are hashed in pairs, building a binary tree. The Merkle root (tree root hash) is stored in the block header. Changing any transaction changes the Merkle root — instantly detectable.

Alle transacties in een blok worden in paren gehasht, waardoor een binaire boom ontstaat. De Merkle root (boomwortelhash) wordt opgeslagen in de blokheader. Het wijzigen van een transactie verandert de Merkle root — direct detecteerbaar.

2

Chain of Hashes (Tamper Evidence)Keten van Hashes (Manipulatiebewijs)

Each block header contains the hash of the previous block header. Changing any historical block changes its hash, which invalidates all subsequent blocks. Makes history immutable without controlling >50% of hash power.

Elke blokheader bevat de hash van de vorige blokheader. Het wijzigen van een historisch blok verandert de hash, waardoor alle volgende blokken ongeldig worden. Maakt geschiedenis onveranderlijk zonder >50% van de rekenkracht te controleren.

3

ECDSA Signatures (Wallet Ownership)ECDSA Handtekeningen (Wallet Eigendom)

Bitcoin uses secp256k1 ECDSA; Ethereum uses the same. Your private key signs transactions; nodes verify with your public key. The wallet address is derived from a hash of the public key — you never expose the public key until you spend.

Bitcoin gebruikt secp256k1 ECDSA; Ethereum gebruikt hetzelfde. Je privésleutel ondertekent transacties; nodes verifiëren met je publieke sleutel. Het walletadres is afgeleid van een hash van de publieke sleutel — je onthult de publieke sleutel pas als je uitgeeft.

4

Proof of Work (Hash Puzzle)Proof of Work (Hash Puzzel)

Miners repeatedly hash block_header + nonce until the output starts with enough zero bits. Requires enormous computation to find — but trivial to verify. This is the consensus mechanism securing Bitcoin.

Miners hashen herhaaldelijk block_header + nonce totdat de uitvoer begint met genoeg nul-bits. Vereist enorme rekenkracht om te vinden — maar triviaal om te verifiëren. Dit is het consensusmechanisme dat Bitcoin beveiligt.

Post-Quantum Cryptography (PQC)Post-Quantum Cryptografie (PQC)

A sufficiently powerful quantum computer running Shor's algorithm can factor large integers and solve discrete logarithms in polynomial time — breaking RSA, DH, DSA, and all ECC. Grover's algorithm halves the effective security of symmetric ciphers (AES-128 → 64-bit security). NIST completed its PQC standardization in 2024. Migration is urgent: attackers are collecting encrypted traffic now to decrypt later ("harvest now, decrypt later").

Een voldoende krachtige kwantumcomputer die Shor's algoritme draait kan grote gehele getallen ontbinden en discrete logaritmen oplossen in polynomiale tijd — waardoor RSA, DH, DSA en alle ECC worden gebroken. Grover's algoritme halveert de effectieve veiligheid van symmetrische cijfers (AES-128 → 64-bit veiligheid). NIST voltooide zijn PQC-standaardisatie in 2024. Migratie is urgent: aanvallers verzamelen nu versleuteld verkeer om later te ontsleutelen ("harvest now, decrypt later").
